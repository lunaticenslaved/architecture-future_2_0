# Задание 5. Технический радар «Будущее 2.0»

Технологии **и** архитектурные паттерны. Согласован с целевой архитектурой ([`../Task3Advanced/01-c4-target-architecture.md`](../Task3Advanced/01-c4-target-architecture.md:1)) и событийным подходом ([`../Task4Advanced/justification.md`](../Task4Advanced/justification.md:1)).

## Кольца

- **Adopt** — целевой стандарт, использовать по умолчанию.
- **Trial** — готово к продовому пилоту на ограниченных кейсах.
- **Assess** — перспективно, прототипировать и оценивать.
- **Hold** — не начинать новое / выводить (легаси и антипаттерны).

## Квадранты

1. Языки и фреймворки · 2. Платформы и инфраструктура · 3. Данные и аналитика · 4. Техники и архитектурные паттерны.

## 1. Языки и фреймворки

| Элемент | Тип | Кольцо | Обоснование |
| --- | --- | --- | --- |
| Golang (финтех) | Технология | Adopt | Действующий стек; конкурентность для событийных потребителей и платежей |
| Java/JVM | Технология | Adopt | Экосистема Kafka/Flink/Debezium на JVM, переиспользование компетенций |
| Python (мед. ИИ) | Технология | Adopt | Действующий стек ИИ; ML, инференс, потоки признаков |

| Power Builder | Технология | Hold | Легаси-UI; переносится на доменные UI + портал |

## 2. Платформы и инфраструктура

| Элемент | Тип | Кольцо | Обоснование |
| --- | --- | --- | --- |
| Apache Kafka | Технология | Adopt | Магистраль слабой связности; pub/sub вместо point-to-point |
| Schema Registry | Технология | Adopt | Avro-контракты + BACKWARD; управляемая эволюция схем |
| Terraform / IaC | Технология | Adopt | Воспроизводимая инфраструктура, гео-среды на регион |
| Облако (Lakehouse-среда) | Технология | Adopt | Эластичность под сотни ТБ, среда на домен/регион, data residency |
| Kubernetes | Технология | Trial | Стандарт исполнения сервисов; вводится с ростом числа доменов |
| GitOps | Технология | Trial | Декларативные деплои поверх IaC; нужен зрелый CI |
| Service Mesh | Технология | Assess | mTLS/трафик при росте сервисов и гео; избыточен на пилоте |
| Apache Camel ESB | Технология | Hold | Легаси-шина p2p; лишь временный ACL-мост, вывод к стадии 3 |
| On-prem DWH-железо | Технология | Hold | Капзатраты и потолок вертикали; заменяется облаком |

## 3. Данные и аналитика

| Элемент | Тип | Кольцо | Обоснование |
| --- | --- | --- | --- |
| Data Lakehouse | Технология | Adopt | Единое хранилище сырых/подготовленных данных под сотни ТБ |
| CDC / Debezium | Технология | Adopt | Захват изменений из легаси без синхронных зависимостей |
| ClickHouse | Технология | Trial | Секундные отчёты вместо часов; пилот на потоковых витринах |
| Apache Flink | Технология | Trial | Near-real-time наполнение витрин; сложнее в эксплуатации |
| Data Catalog / lineage | Технология | Trial | Обнаружимость продуктов и происхождение; основа self-service |
| Self-service BI + семантический слой | Технология | Trial | Портал-витрина; замена монолитных кастомизаций Power BI |
| Feature Store (ИИ) | Технология | Assess | Переиспользование признаков между моделями |
| Data Quality / observability данных | Технология | Assess | Контроль качества и SLA данных-продуктов |
| MS SQL Server 2008 (DWH) | Технология | Hold | EOL, риск ИБ/комплаенса, потолок масштаба; вывод через CDC/ACL |
| Монолит Power BI поверх DWH | Технология | Hold | Хрупкие прямые запросы к DWH; на семантический слой + портал |

## 4. Техники и архитектурные паттерны

| Элемент | Тип | Кольцо | Обоснование |
| --- | --- | --- | --- |
| Event-Driven Architecture | Паттерн | Adopt | Основа слабой связности и устойчивости |
| Data Mesh | Паттерн | Adopt | Доменное владение данными-продуктами; нет «узкого горла» DWH |
| Data Contracts | Паттерн | Adopt | Явные контракты поверх Schema Registry |
| DLQ | Паттерн | Adopt | Обработка невалидных/зависших сообщений без потерь |
| Anti-Corruption Layer | Паттерн | Adopt | Изоляция доменов от легаси; управляемый вывод |
| RBAC/ABAC | Паттерн | Adopt | Доступ к срезам; медданные вне аналитики |
| Observability / SLO | Паттерн | Adopt | Метрики/трейсинг/SLO для распределённой платформы |
| Outbox | Паттерн | Trial | Надёжная транзакционная публикация событий |
| Contract-first / Schema Governance | Паттерн | Trial | Дизайн контрактов до реализации; процессная дисциплина |
| CQRS | Паттерн | Assess | Разделение чтения/записи для витрин; точечно |
| Event Sourcing | Паттерн | Assess | История фактов как источник истины; там, где нужен аудит |
| Multi-region / Data Residency | Паттерн | Assess | Гео-изоляция ПДн; ось «География» |
| Синхронные point-to-point | Паттерн | Hold | Жёсткие зависимости и каскадные отказы |
| Логика/трансформации в DWH | Паттерн | Hold | Единая точка изменений и регрессия; в агрегаты и dbt |
