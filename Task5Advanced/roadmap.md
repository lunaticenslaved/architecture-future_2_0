# Задание 5. Стратегический роадмап внедрения Data Mesh

Роадмап перехода к событийной платформе и Data Mesh, привязанный к стадиям трансформации ([`../Task3Advanced/01-c4-target-architecture.md`](../Task3Advanced/01-c4-target-architecture.md:58)) и бизнес-целям «Будущее 2.0». Диаграмма: [`diagrams/roadmap.puml`](diagrams/roadmap.puml:1).

## Ключевые роли и зоны ответственности

| Роль | Зона ответственности |
| --- | --- |
| **Data Product Owner** (в домене) | Владеет данными-продуктом: контракт, SLA, качество, дорожная карта продукта, приоритеты потребителей |
| **Data Engineer** (в домене) | Строит пайплайны/потоки (Flink), топики, витрины; реализует контракты и трансформации (dbt) |
| **BI-аналитик** | Собирает отчёты/метрики через self-service портал и семантический слой; формулирует потребности к продуктам |
| **Platform / Enabling team** | Общая платформа: Kafka + Schema Registry + DLQ, Lakehouse, ClickHouse, IaC/Terraform, шаблоны и «золотые пути»; обучает домены |
| **Data Governance / Steward** | Каталог, lineage, стандарты контрактов, классификация данных, RBAC/ABAC, приватность (медданные вне аналитики) |
| **Domain team** | Доменные сервисы-продюсеры событий; бизнес-логика в агрегатах, публикация фактов |
| **SRE** | Надёжность платформы: SLO/observability, мониторинг DLQ, инциденты, ёмкость, гео-среды |

---

## Этап 1. Пилот (стадия 1, 0–6 мес)

**Бизнес-цель (промежуточное состояние ~2 мес):** архитектура согласована, границы доменов определены.

- **Цели:** доказать событийный подход на 1–2 доменах (Финтех или поток пациентов); заложить единые принципы.
- **Ключевые активности:** развернуть Kafka + Schema Registry + DLQ; описать границы доменов и контракты; CDC/Debezium из легаси DWH; первый данные-продукт; ACL-адаптер к DWH.
- **Вовлечённые роли:** Platform/Enabling (backbone, шаблоны), Data Product Owner + Data Engineer пилотного домена, Data Governance (каталог схем), SRE (базовый мониторинг).
- **Артефакты/результаты:** реестр схем и конвенции событий, DLQ-политика, 1–2 данных-продукта, ACL-мост, карта границ доменов.
- **KPI:** ≥1–2 данных-продукта в каталоге; 100% событий пилота под контрактом в Schema Registry; DLQ настроен; отчёт пилота формируется за минуты (было — часы).

## Этап 2. Масштабирование (стадия 2, 6–18 мес)

**Бизнес-цель (финальное состояние ~1 год):** портал самообслуживания работает, пользователи работают в доменах.

- **Цели:** распространить подход на критические домены; запустить потоковые витрины и self-service портал.
- **Ключевые активности:** новые домены как продукты (топики + схемы); Flink → потоковые витрины → ClickHouse; портал + семантический слой + RBAC/ABAC; ACL для Camel/DWH; Outbox в критических сервисах; каталог/lineage.
- **Вовлечённые роли:** все домены (Data Product Owner + Data Engineer), Platform/Enabling (масштаб платформы), BI-аналитики (переход на портал), Data Governance (контракты, доступы), SRE (SLO, гео).
- **Артефакты/результаты:** портал самообслуживания, потоковые витрины, каталог с lineage, ACL-мосты над Camel/DWH, набор данных-продуктов по доменам.
- **KPI:** ≥6 данных-продуктов; self-service adoption ≥60% аналитиков; ≥80% отчётов на портале/ClickHouse; покрытие контрактами ≥90%; время формирования отчёта — секунды/минуты.

## Этап 3. Поддержка и эксплуатация доменов (стадия 3, 18–36 мес)

**Бизнес-цель (долгосрочное ~3 года):** событийная платформа, масштабирование по продуктам/географии/данным.

- **Цели:** отказ от синхронных point-to-point; вывод легаси; доменная аналитика на потоках; устойчивая эксплуатация.
- **Ключевые активности:** вывод SQL Server 2008/Power Builder/Camel; снятие ACL-мостов; гео-среды (data residency); онбординг новых направлений (Фарма/Медтехника) как доменов; операционная модель Data Mesh.
- **Вовлечённые роли:** SRE + Platform (эксплуатация, SLO), Data Governance (зрелый governance), домены (владение продуктами), Data Product Owner (эволюция контрактов).
- **Артефакты/результаты:** выведенные легаси-системы, гео-распределённые среды, операционные ранбуки/SLO, каталог данных-продуктов по всем доменам.
- **KPI:** 0 синхронных point-to-point на критическом пути; легаси DWH/Camel выведены; self-service adoption ≥85%; ≥2 региона; near-real-time витрины по ключевым доменам; накопленная экономия TCO выходит в плюс ([`tco-analysis.md`](tco-analysis.md:1)).
